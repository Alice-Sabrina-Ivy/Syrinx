## Hard rules (load-bearing — DO NOT VIOLATE)

### 1. PR creation requires explicit user approval

Branches, commits and pushes are autonomous. **Run `gh pr create` only after the user explicitly says "open the PR" (or equivalent)** — for every PR, however small. Approval of a fix's *content* is not approval to open its PR; a task that says "PR opened" or "deliverable surfaced" means "branch ready for review, STOP before `gh pr create`". At the stop, push, give the branch name and a one-paragraph summary, and wait. (Since 2026-05-05, after PRs #70 and #71 were opened out of process.)

### 2. Spawned-process cleanup

**Kill only the PID you spawned:** `taskkill /pid <PID> /T /F` (`/T` tree-kills renderer / GPU / network children). Never `taskkill /IM chrome.exe`, `Get-Process chrome | Stop-Process` or any other name-based selector: Alice runs Chrome across several monitors with active work, and a pattern-matched kill loses it. Non-negotiable.

- Launch every spawned Chrome with a unique `--user-data-dir=<temp dir per run>`; otherwise it merges into her running instance, ignores `--remote-debugging-port`, and your PID isn't the debug target.
- Register cleanup on `process.on("exit")`, `SIGINT`, `SIGTERM` and `uncaughtException`, then remove the per-run profile dir. Template: [scripts/desktop-diag-capture.js](scripts/desktop-diag-capture.js). Puppeteer's `browser.close()` is fine.
- Never run `chrome.exe --version` on Windows: it opens a window on her real profile. Read the file's version instead: `(Get-Item '<path to chrome.exe>').VersionInfo.ProductVersion`.

### 3. Measurements before tuning changes

Any optimization or tuning work on `boersma-ac.js`, `pitch-worker.js`, `dsp-worker.js`, `gender-worker.js`, `pitchSmoothing.js`, `pitchGate.js`, or `cpp.js` produces a measurement file in `measurements/` *before* code changes are proposed — changes in these files are grounded in numbers, not intuition. See §"Measurements & empirical results" for conventions and oracles.

**Cue-strip modules (user-approved 2026-10-07):** the same rule covers [src/resonance/resonance-worker.js](src/resonance/resonance-worker.js), [src/resonance/overloadGuard.js](src/resonance/overloadGuard.js), [src/resonance/resonanceCue.js](src/resonance/resonanceCue.js), [src/resonance-lab/vtln.js](src/resonance-lab/vtln.js), [src/resonance-lab/lab-engine.js](src/resonance-lab/lab-engine.js), [src/ml/heard-as.js](src/ml/heard-as.js), [src/ml/heardAsCalibration.js](src/ml/heardAsCalibration.js) and [src/audio/vocal-weight-level.js](src/audio/vocal-weight-level.js). ## Working rules in this project

- **Hosting:** GitHub (`origin` = github.com/alice-sabrina-ivy/Syrinx; `gh` for PRs and issues). The Forgejo instance in the user-level notes is not used here.
- **Decisions:** when a guard fails or something ships by choice, the row records "user decision YYYY-MM-DD" and the accepted cost. Never present a failed guard as passed. Pre-registration and real-chain measurement: hard rule 3, §Binding methodology rules.

## Project Overview

Syrinx is a browser-based voice training toolkit providing real-time resonance and pitch analysis. It runs entirely client-side with no backend — all audio processing happens in the browser. Serves voice training in any direction: the user picks a training direction on every load (more feminine / more masculine / androgynous / just exploring) and targets follow it — none is assumed (2026-10-07).

Live demo: https://alice-sabrina-ivy.github.io/Syrinx/

## Commands

- **Dev server:** `npm run dev` (HTTP localhost only); **phone testing:** `npm run dev:mobile` (§Mobile testing)
- **Production build:** `npm run build` (outputs to `dist/`, untracked — CI deploys it); **preview:** `npm run preview`; **lint:** `npm run lint`
- **Unit tests (what CI runs):** `npm run test:unit` — every self-contained `tests/**/*-test.js` plus a few regression scripts ([scripts/run-unit-tests.mjs](scripts/run-unit-tests.mjs); `--list` shows what runs and what's skipped and why). A new `*-test.js` joins CI automatically: keep it self-contained (committed fixtures; skip gracefully when gitignored corpora are absent) or add it to the runner's SKIP list with the reason.
- **Local bundles:** `npm run test:dsp` (needs the gitignored PTDB/FDA corpora), `npm run test:resonance-lab`

No test framework is set up. Test files are runnable Node scripts that print pass/fail and exit non-zero on failure.

### Capture architecture

[src/audio/captureSource.js](src/audio/captureSource.js) `createCaptureSource()`: **`mstp`** (main-thread `MediaStreamTrackProcessor` → `AudioData` → `MessageChannel` → workers; Chrome desktop + Android, Safari ≥ 26) or **`audiocontext`** (`MediaStreamAudioSourceNode` → `AudioWorkletNode` → `MessageChannel`; Firefox). `pickKind()` = feature detection, no UA gating; `?capture=` overrides. **Runtime fallback:** any MSTP start failure (constructor / `getReader()` throws, the reader errors, `copyTo` rejects, no frame in 5 s) releases the reader without stopping the track and retries AudioContext on the same `MediaStream`; before the first frame MSTP rejects instead of calling `onError`. Recorded as `fallbackFrom`, `audioInfo.captureFallback`, a diag error and a console warning. Not a fallback: `?capture=mstp` (fails loudly), a track ended before the first frame. `NotAllowedError` → "Microphone access denied…". **Next capture item: Firefox-mobile worker-MSTP** (Chrome 147 mobile has no worker MSTP); do not start other capture work before it.

## Architecture

### Audio Pipeline (six layers, each on its own thread; the ML worker only while the heard-as panel is on)

1. **Capture** (MSTP reader or `public/capture-processor.js`): ~25 ms chunks to every registered consumer port — DSP, pitch, resonance, ML (panel on), the lab (once opened), Voice Shaper (while recording); `disconnectConsumer(port)`. Pre-allocated; each consumer gets its own copy (transferables detach).
2. **DSP worker** ([dsp-worker.js](src/dsp/dsp-worker.js)): 100 ms ring. Formants: Burg LPC at ~12 kHz every 6th frame, order `min(16, 2·ceil(5·SR/11000))`; the relayed `pitch-hint` picks the male / female rate and the 5000 / 5500 Hz ceiling (female default). HNR ([hnr.js](src/dsp/hnr.js)) on the last 70 ms every 6th frame; tilt; intensity. CPP only with `cpp: true`. Zero-GC; no pitch here.
3. **Pitch worker** ([pitch-worker.js](src/dsp/pitch-worker.js)): 16 kHz streaming linear resample → notch → 1280-sample buffer → Boersma-AC per 25 ms chunk, L = 2. FireRedVAD only when `init` carries `vad: { modelBase, source }` (Node harnesses don't pass it and get the old behaviour); once loaded the worker is an in-order promise chain. Post-decode: ghost veto → above-range null → harmonic guard. Posts `{ pitch, confidence, voiced, ts, contextTime, inferMs?, notchedFreqs?, vad? }`; **invariant pitch ≠ null ⟺ confidence ≥ 0.5** (the silence gate relies on it); ready = `{ detector: "boersma-ac", device: "js", threshold }`.
4. **Resonance worker** ([resonance-worker.js](src/resonance/resonance-worker.js)): fetches `public/resonance-lab/vtln_warp.json` + `reference.json`; posts `{ type: "state", u, raw, uPlain, n, fill, voicedS, clamp, verdict, startU, shownStartU, startProgress, sinceResumeS, framesDropped, narrowband, perf? }` every 200 ms of audio (`u` / `raw` null until the narrowband detector decides); status `loading | ready | error | overloaded` (an `error` with `recovering` → the column's "restarting", with `reason: "load"` → "reload").
5. **ML worker** ([gender-worker.js](src/ml/gender-worker.js)): only while the panel is on (terminated, port disconnected when off). Transformers.js; 0.75 s window; decision every 150 ms, classifier every 450 ms (`classifyDue`; the hop is timed start to start); Silero VAD v6.2.3 in the same worker (`Alice-Sabrina-Ivy/silero-vad-v6.2.3-onnx` at a pinned commit via `loadVerifiedModel`; 512-sample frames + 64-sample context, LSTM state carried), chunks in order. Posts `{ score, confidence, ts, logit, audioMs, spanId, mode, inferMs?, vadMs? }`, `{ type: "scored", … }` between classifier runs, `voice-state`, `speech-detector`. ONNX Runtime WASM ships with the app ([ort-runtime-files.js](src/ml/ort-runtime-files.js) + `pointOrtAtAppRuntime`); `lab-worker.js` points its own Transformers.js copy at the same runtime; a Transformers.js upgrade picking another variant, or a nested second `onnxruntime-web`, fails `ort-runtime-files-test.js`. Labels parsed by name (`femaleScoreFromResult` / `femaleLogitFromResult`; id2label `{0: male, 1: female}`), null if unknown.
6. **Main thread** ([useAudioPipeline.js](src/audio/useAudioPipeline.js)): worker lifecycle; latest pitch merged into each DSP frame (`latestPitchRef`); pitch median-3 (`smoothingBufferFor`); formants median-smoothed, > 500 Hz jumps rejected; 5 s silence hold, 400 ms pitch hold; history in refs; setState ~5 fps. `handlePitchMessage` (via its ref) sends the DSP worker a `{ pitch }` hint and ML / resonance one shared hint object (resonance gets a `voiced: false` copy on hops the voice gate hides), then feeds the heard-as aggregator, steadiness, the pitch-only warning (every posted frame from Start, panel on or off) and, last, Voice Shaper's tap.
   - **Silence gate:** suppress only when intensity < −50 dB AND confidence < 0.5 for ≥ 3 frames (AND is deliberate, PR #74); pre-warmup frames (confidence null) gate on intensity alone.
   - **Paint gate / voice gate:** Current-state rows. The hook breaks the line before a painted jump ≥ `EXCURSION_SEMI` and shows "—" while a fresh off-level pitch is suppressed; the voice-gate mask is applied after smoothing / paint gate / silence gate / hold, the dim 5 s hold keeps the last *shown* pitch and HNR (`shownHnr`), frames record `painted` and `voiceGate` ("voice" | "hidden" | "novoice"); session stats keep `voiced` / `f0`.
   - **Utterance gate** ([utterance-gate.js](src/ml/utterance-gate.js); ML windows, resonance bins): with Silero hints, a speech utterance opens on 150 ms of frames with p ≥ 0.5 and closes after 1 s; a window counts if the newest speech frame is ≤ 500 ms old, ≥ 15 % of frames are speech and ≥ 40 % is after the onset. Without hints, the pitch gate on the **audio clock** (hint = capture time, now = newest chunk; wall-clock broke it): opens on ≥ 150 ms of voicing (a > 100 ms gap breaks the run), closes after 1 s. ≥ 95 % voiced with ≤ 2 st spread over 1 s = held phonation ("needs running speech"; flat-intonation speech trips it ~7 % of the time). The absolute silence floor always applies; fails open to peak ≥ 0.05 if the pitch feed is > 2 s stale. `speechMinVoicedMs` / `speechMinVoicedRunMs` exist but are off (whisper decision A, [whisper-voicing-2026-10-07.md](measurements/whisper-voicing-2026-10-07.md)).

### Canvas Visualization Strategy

History arrays live in refs, read directly by canvas draw code; all canvases use ResizeObserver + devicePixelRatio scaling. **Main-thread budget** ([main-thread-cpu-2026-10-08.md](measurements/main-thread-cpu-2026-10-08.md)):
1. No uncapped rAF loop, none while idle (`subscribeTrace` / `notifyTrace`; [traceRedrawScheduler.js](src/components/traceRedrawScheduler.js), `tests/audio/trace-redraw-test.js`).
2. No layout reads per frame or point — geometry once per size; the one per-draw read is `window.devicePixelRatio`, because a DPR-only change fires no event.
3. Static layers cached in an offscreen canvas.
4. Animate only transform / opacity on HTML elements (the cue-strip thumb is HTML over the SVG); SVG, `left`, colour or shadow transitions re-run the main-thread pipeline every frame.

### Key Design Decisions

- Capture → worker MessagePorts, no main-thread audio relay. getUserMedia runs with `echoCancellation: false` ([useAudioPipeline.js](src/audio/useAudioPipeline.js)), so anything that plays audio (e.g. Voice Shaper) stays silent while a session records: saved sessions must not contain played-back audio.
- One confidence threshold (0.5) gates pitch reporting AND seeds the silence gate — no ambiguous middle band.
- Formants use the relayed pitch hint with one frame of lag; at 44.1 / 48 kHz an octave-down hint changes only the 5000 / 5500 Hz ceiling ([formant-lpc-order-2026-10-03.md](measurements/formant-lpc-order-2026-10-03.md)).
- The gender model runs on **WASM, not WebGPU** (WebGPU threw runtime validation errors and was 4.7× slower; [gender-model-latency-2026-07-19.md](measurements/gender-model-latency-2026-07-19.md)); `inferenceInProgress` drops overruns.
- The pitch and ML workers (and the lab's pitch replica) resample with streaming linear interpolation (`createStreamingResampler`; little speech energy above 8 kHz, browsers low-pass mic input); the resonance worker's vtln analysis stream and Voice Shaper use the anti-aliased sinc resampler ([sinc-resampler.js](src/resonance-lab/sinc-resampler.js)).
- Rolling medians; a 5 s silence hold; session frames flushed to IndexedDB every 1 s; targets follow the user's direction, never assumed.
- **HF Hub `wav2vec2` tag on the gender model is wrong but load-bearing**: `config.json` in the gender-model repos (production `Alice-Sabrina-Ivy/voice-gender-classifier-onnx-q8-v2`, and the older `-q8`) deliberately sets `model_type: "wav2vec2"` (actual architecture: ECAPA-TDNN) because Transformers.js routes pipelines off `model_type` and `ecapa-tdnn` isn't a registered type. **Changing the field breaks production at `pipeline()` load time.** Leave it.

### Private session data

The user's practice-session recordings and their label files (per-session parquet frame tables: speaker labels, Praat-derived f0 / formants / HNR) are **private and local-only — never committed**. Scripts reach them through the `SYRINX_SESSIONS_DIR` environment variable (`$SYRINX_SESSIONS_DIR/<YYYY-MM-DD>/session.wav` + `acoustic/frames_enrollment-2026-05-07-v2.parquet`), the resonance lab via `rlab.paths.sessions_dir()` (its test set is `sessions`); never a hard-coded path; explicit CLI overrides (`--sessions-root`, `--root`, `--wav`) still win, and a script that needs the folder fails with a clear message when the variable is unset. Measurement files cite these paths as `$SYRINX_SESSIONS_DIR/...`. Never write the private source project's name or the names of other people in the recordings into the repo, commit messages or PRs: say "the private session recordings" and "a second voice in the recordings" (code key `second`, speaker code 2).

**Results stay private too (2026-10-05).** This repo is public. Results computed on the private session recordings — or on any other recording of the user's own voice (live-mic diag snapshots, attach-harness captures) — are written to the user's private project, **never to `measurements/` in this repo**. `measurements/` holds public-data results only: FDA, PTDB-TUG, Hillenbrand, vocadito and other public corpora, synthetic stimuli, and timing / CPU / device diagnostics. A public measurement note may describe the method of a session run and state its outcome in one aggregate sentence, then say "Results on the private session recordings are kept outside this repository." — no session tables, per-session numbers, clip lists or session-scored rows. The session-oracle, pitch-benchmark, pitch-precision, steadiness and notch-adversarial scripts already default to the gitignored `build/`; `scripts/pitch-shootout-analyze.py` and `scripts/compare-praat-swift-sessions.py` take their output path as an argument and document a `build/` path — keep it there. The diag-capture harnesses save to the gitignored `measurements/{desktop,mobile}-diag-runs/`; never promote a capture of the user's own voice from there into a committed file. The session-derived measurement files and sections that predate this rule were moved to the private project on 2026-10-05; where a public note cites them it says "(private measurement, kept outside this repo)". The resonance lab keeps every result, including rubric item R6 (scored on the `sessions` set), under the gitignored `build/resonance-lab/`; R6 scores, AUCs and orderings never go into `measurements/`. `scripts/resonance-lab/lab_tables.py` prints R6 columns and a result verdict that includes R6 by default — for a public note run it with `--public` (drops the R6 columns, judges the result column on R1–R4 only); the per-family summary scripts (`candidates/learned-envelope/summ.py`, `candidates/vtln-warp/dev/tsum.py`) and the `build/` leaderboard also print R6 values and a pass flag that includes R6, so never paste their output as-is.

### Binding methodology rules

- **Multi-frame streaming evaluation is canonical for pitch.** Step 25 ms hops over each recording at production cadence, simulating the production rolling buffer. Single-window-per-file produces noise-dominated numbers (preserved only as historical context in session-1 files). Evaluation regime must match the stimulus's stationarity — the wrong helper regime once produced a 7× artifact (F p95 210 vs 28 Hz); see [INVESTIGATIONS.md](INVESTIGATIONS.md).
- **Score each detector at its own response center**, and note **PTDB-TUG reference timestamps are offset ~+20 ms** vs the loader's `i*hopMs` convention — pre-2026-06-09 PTDB numbers in the measurement history should be read with this in mind ([boersma-ac-tuning-2026-06-09.md](measurements/boersma-ac-tuning-2026-06-09.md)).
- **Production paths must be measured, not just harnesses.** Harnesses set config via `globalThis.__VAR` overrides; production doesn't. The fallback-when-unset path is part of the ship surface — at least one end-to-end run through the real production init sequence before any ship claim. (PR #68 shipped harness-only L=2 numbers while production silently ran L=5; the named-default-constant convention exists so this can't recur silently.)
- **Measure on the production runtime.** Node ORT is ~18× faster than browser ORT-WASM; mobile WASM another 2–4.5× slower than desktop depending on architecture. Ship decisions anchor on the gating-constraint hardware (browser, mobile).
- **Pitch accuracy targets are gender-symmetric.** The tool serves voice training in any direction — transmasculine, transfeminine, cis singers and speakers. Ship decisions optimize a gender-symmetric metric (e.g. `max(F_error, M_error)`), never female accuracy alone. Demographic assumptions don't go into ship-criterion math without explicit justification.
- **Real-speech corpora are the only signals that distinguish good from bad pitch settings.** Synthetic-stimulus suites are regression guards at best, insensitive for parameter selection (84-cell sweep, 2026-05-04). Synthetic fixtures also can't calibrate the silence gate — real speech has much lower voicedness than a clean fixture at the same RMS (PR #74).

### Methodology lessons index (full arcs in [INVESTIGATIONS.md](INVESTIGATIONS.md))

- **Field-benchmark first when an algorithm class is suspect** (pYIN: a 2 h literature check after 2 days of sweeps).
- **Architecture-runtime interaction beats parameter count** (desktop:mobile WASM: ECAPA-TDNN ~2.4×, wav2vec2-base ~4.5×, wav2vec2-large ~21×).
- **Don't assume the current ship works without measuring it** (mobile gender inference ran at ~2100 ms for weeks).
- **Don't transfer thresholds across decision contexts.**
- **Batch and streaming inference attribute frames differently** — allow for attribution latency in streaming tests.
- **Check quantized vs fp32 before declaring a floor** (the "m45 noise floor" was q8 damage, 2026-07-19).
- **Score the user's actual registers** — low, target (160–400 Hz) and switches, under gender-symmetric guards (2026-10-03).
- **Reference selection bias** — use a majority across method families plus a spectral odd-multiple arbiter, not a reference that keeps only frames an AC tracker agrees with (2026-10-03).
- **Committed oracles must mirror the shipped chain** — confirm bit-exact parity with the real worker / hook before trusting an oracle number (2026-10-03).

- **Real-noise false voicing:** measured before the voice gate, on the deleted branch `realnoise-false-voicing` (results not kept): ~24 % of 279 real noise-only clips' time painted a false line, about half from the 400 ms pitch-hold bridge. The voice gate (default on) removes ~80 % of the false line on fresh noise ([firered-confirmation-2026-10-21.md](measurements/firered-confirmation-2026-10-21.md)); the bridge rework branch was deleted and not kept.
- **Tonal interference** (beyond the notch row's gaps): speed-varying fans evade the notch; a mid-session interferer is notched only after ~20 s and paints in pauses meanwhile; voice within ±2 % of a line or its octave is vetoed; the inter-harmonic guard floor is deferred (raises target-band half-pitch); field-noise validation pending. Unconfirmed single-reviewer reports (treat as open): a hum masked by low-register speech is never notched; hum ghosts paint in short pauses; a hold over ≤ ~9 dB SNR room noise is notched ~5 s in; `onsetDb` matters in room noise. A harmonic-rich interferer near a multiple of F0 can capture the octave — largely mitigated for stationary interferers by the notch (2026-07-19), not for non-stationary ones; characterized under SwiftF0 only. User-side fix: `npx serve scripts/ambient-noise-probe` (narrow 75–300 Hz peaks ≥ 15 dB are likely culprits). PENN ruled out 2026-05-13 (6–7× slower in browser WASM, 24× larger, needs COI headers); adaptive notch front-end not pursued.
- **Residuals of the 2026-10-03 target-voice pass** (accepted 2026-10-04; no fallback passes all guards — contested-pair arbitration, `maxPitchHz` 600, `EXCURSION_SUSTAIN` 10–12 were measured; [target-voice-combined-validation-2026-10-03.md](measurements/target-voice-combined-validation-2026-10-03.md) §14): low-voice octave-up under strict refs > +0.3 pp (octave arbitration; listening adjudication would settle it); Hillenbrand men −0.77 pp (800 Hz search; `maxPitchHz` 600 still −0.60 and reopens aliasing); painted up-spike runs rise while the total falls; target-voice octave-down reduced, not gone (stronger arbitration breaks the low-voice guard — the next step only once the low-band references are adjudicated, e.g. listening-labelled disputed frames); vowel-onset 3f / 4f locks; locks ≥ 8 raw frames paint their tail; quiet-mic transients validated on synthetic clicks only; above-range phonation shows as a gap.
