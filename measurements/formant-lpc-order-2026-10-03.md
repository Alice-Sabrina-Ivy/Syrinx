# Formant LPC order at the production capture rates — 2026-10-03

**Verdict: the reported defect is real. Fix: one rate-derived LPC-order rule for both pitch branches, with the formant code moved into a shared module that the accuracy test imports.**

In the male branch of `extractFormants` (pitch hint < 140 Hz), the LPC order was fixed at 10. At 44.1/48 kHz capture the analysis rate is 11.025/12 kHz, and order 10 is too low there. On Hillenbrand men at 48 kHz, F2 mean error is **265 Hz with 17.6 % gross errors (>20 %)**. A rate-derived order fixes it: `min(16, 2·ceil(5·SR/11000))` gives 12 at 11–12 kHz, 8 at 8 kHz and 16 at 16 kHz. With that order, men score **107 Hz / 7.4 %**. Women's numbers don't change at any capture rate ≥ 11 kHz.

The order now follows the analysis rate, not the speaker. As a result, an octave-down pitch hint changes only the 5000/5500 Hz pole-selection ceiling at 44.1/48 kHz. That changes the reported F1–F3 on ≤ 0.2 % of files. The fix was also checked on real voice from private session recordings; results on the private session recordings are kept outside this repository.

`tests/dsp/formant-accuracy-test.js` carried an inline copy of the formant code and only ran at the corpus's native 16 kHz. At 16 kHz the male branch analyses at 8 kHz, where order 10 is close to right, so the test never saw the defect. The change moves the formant code into `src/dsp/formants.js`. The worker and the test both import it. The test adds 44.1/48 kHz cases and an octave-down-hint case.

## Motivation

The phase-1 bug sweep of the 2026-10-03 half-pitch investigation (scratch probe `build/investigate-2026-10-03/bugs-dsp/p7-formants.mjs`, gitignored) reported that the male branch is under-fitted at 48 kHz. It claimed F2 mean error 269 → 108 Hz and gross 17.7 → 7.5 % with order 12. This pass tried to refute that claim on several axes:

- upsampler choice;
- reference convention;
- forced versus natural branch routing.

It also swept the order and the analysis rate per branch, and checked two related questions:

- (a) A higher voice decoded at half pitch sends an octave-down hint that drops it below the 140 Hz male/female switch. What does the switch, and that octave-down hint, do to the formants?
- (b) Is the formant-ceiling and pole-selection logic sound?

## Harness

All harness files are scratch in `build/measure-2026-10-03/formants-lpc/` (gitignored, not committed; the landed regression guard is `tests/dsp/formant-accuracy-test.js`). Code baseline: 41f73d8, whose `src/` tree is identical to the merge f92b11a this change lands on.

- **`dspw_prod.mjs`**: a verbatim copy of `src/dsp/dsp-worker.js` at 41f73d8. The only edits are the cpp.js import path and an added `export { extractFormants }`.
- **`dspw_var.mjs`**: generated by `make-var.mjs`. It is the verbatim worker plus `extractFormantsCfg(buffer, pitch, cfg, info)`, which reuses the worker's own pre-emphasis, Hamming window, `decimateWithFilter`, `burgLPC` and `findPolynomialRoots`. Branch threshold, decimation, order and ceiling are configurable. It optionally returns every raw pole, so pole selection can be swept offline. The only other edits are `MAX_LPC_ORDER` raised from 16 to 24 (array sizing only) and an iteration counter on the root finder (no change to the numbers).
- **Corpus**: Hillenbrand et al. (1995) men (540 files) and women (576 files), all files present, no 5-per-vowel subsetting unless stated.
  - The middle 50 ms window is the production `WINDOW_MS`, and is the methodology of the existing test.
  - Primary reference: the vowdata.dat steady-state F1–F3 (the test's convention).
  - Sensitivity reference: the 50 %-duration F1–F3 (vowdata columns 11–13), which matches the middle window more closely.
- **Capture rates**:
  - 16 kHz native;
  - 44.1 and 48 kHz from scipy `resample_poly` (`upsample.py`), with a sensitivity re-run using soxr_vhq;
  - 8 kHz from `resample_poly` 1/2 (`down8k.py`), standing in for narrowband Bluetooth-class mics. MSTP passes the track's native rate through: `captureSource.js` uses `frame.sampleRate`.
- **Metrics**: mean and median absolute error over non-null outputs. "Gross" means |err|/ref > 20 % or no value.

### 3. (a) The pitch-hint switch and the octave-down hint

Hillenbrand routing:

- 67 % of men have F0 < 140 Hz and so take the male branch.
- No women have F0 < 140 Hz.
- 99.5 % of women's f0/2 values are below 140 Hz, so an octave-down hint almost always moves a woman's voice into the male branch.

For **cis women's vowels at 44.1/48 kHz**, the octave-down hint does no F2 harm even in production, because order 10 at 11–12 kHz suits short vocal tracts. At 48 kHz F2 goes 137/9.4 % → 145/8.9 %; at 44.1 kHz it goes 150/10.6 % → 131/8.2 %, i.e. better. F3 does degrade at 48 kHz (108/3.6 → 201/12.5). U costs women-with-an-f0/2-hint at most 0.5 pp of F2 gross at 48 kHz (8.9 → 9.4 %) and 2.4 pp at 44.1 kHz (8.2 → 10.6 %). Either way those frames now score exactly like the true-hint case. On the test subset the same cell reads 99.6 → 107.1 Hz. At **16 kHz** capture the hint is badly harmful in production: F2 128/8.5 % becomes 289/28.6 %, because the male branch drops to 8 kHz analysis at order 10. With U, that case is 131/9.1 %.

The same comparison on real voice from private session recordings (48 kHz, production hint vs true and f0/2 hints) moved the same way as the Hillenbrand result. Results on the private session recordings are kept outside this repository.

**Threshold verdict:** with U, the 140 Hz switch changes only the ceiling at 44.1/48 kHz. At 16 kHz it chooses between 8 kHz/order 8 and 16 kHz/order 16, and both are accurate for both genders. Moving the threshold would not help, so no change is proposed.

### 4. (b) Formant ceiling and pole selection (`python report_ceiling.py`, U rule)

- Ceiling 5000 versus 5500 changes the reported F1–F3 on 0.0 % of men's files and 0.2 % of women's at 48 kHz, and 0.0 % / 0.0 % at 44.1 kHz. The ceiling is a post-filter on poles. It matters only when fewer than three poles fall below it. Removing it entirely (Nyquist) gives the same numbers. Ceiling 4500 trades a little F3 accuracy for more missing values. The logic is sound and inert.
- The `freq > 90` floor is inert. Raising it to 150 or 200 Hz changes nothing.
- The bandwidth cap of < 600 Hz is the one knob with an effect, and only on F3:
  - bw < 800 at 48 kHz: men F3 136/6.4 → 98/3.2 %, women F3 108/3.6 → 76/0.9 %, F2 ±5 Hz.
  - bw < 400 is worse everywhere.

  This is a possible follow-up, not part of this change. F2 is the user-facing value: the dashboard F2 target and the session-history F2 trace.
- Side probe of anti-alias FIR length and cutoff (`node fir-probe.mjs <tapsPerFactor> <cutoff>`). Taps of 32× or 64× the factor, or a cutoff of 0.42, give no gain (F2 within ±5 Hz), so the filter stays unchanged.

## Chosen config and why

**U: `lpcOrder = min(16, 2·ceil(5·analysisSR/11000))` in both branches.** Decimation, the 140 Hz switch and the 5000/5500 ceilings are unchanged. Reasons:

1. It removes the defect at 44.1 and 48 kHz, the rates production actually captures at:
   - 48k men F2 265/17.6 % → 107/7.4 %, F1 41/5.0 % → 29/2.4 %, F3 339/22.0 % → 136/6.4 %;
   - 44.1k men F2 147/10.7 % → 103/8.0 %.
2. For each analysis rate, it is men's measured F2-gross optimum (§1). It reproduces the female branch's existing order at every capture rate ≥ 11 kHz, so women don't change there.
3. It makes the formant path robust to a half-pitch hint on a higher voice. Women at 16 kHz with an f0/2 hint: 289/28.6 % → 131/9.1 %; at 44.1/48 kHz an f0/2-hinted frame now scores exactly like the true-hint case (§3).
4. It also fixes the female branch's floor of 12 at 8 kHz capture: women F2 672/66.7 % → 130/9.1 %.
5. The code gets simpler. `LPC_ORDER_MALE`, `LPC_ORDER_FEMALE` and the dead `LPC_ORDER` go away, and `lpcOrderForRate()` is exported.

The code moves verbatim into `src/dsp/formants.js`. The only refactor is that `decimateWithFilter` takes an explicit length. The worker calls `configureFormants(sampleRate, windowSize)` on `init`, and the module sets itself up for 48 kHz / 50 ms at load, as the worker used to.

The test imports the module, so test and worker can no longer drift apart. The test keeps the 16 kHz case with its original targets (F1 < 80, F2 < 120). It adds 48 and 44.1 kHz cases (F1 < 80, F2 < 160) and a 48 kHz women f0/2-hint case. The upsampled windows come from a band-limited span resampler written in the test.

- The old logic fails the new test: 48 kHz men F1 86.3 and F2 554.5; 44.1 kHz men F2 310.8. Exit 1.
- The landed code passes. The tightest margin is 44.1 kHz women at 144.1 against the 160 target. That cell is limited by women's order-12 fit at 11.025 kHz (see follow-ups) and is unchanged by this fix.

## Rejected options

- **Male order fixed at 12** (the literal claim): correct at 44.1/48 kHz, but at 16 kHz capture the male branch runs at 8 kHz, where order 12 gives men F2 238/25.0 % and women with an f0/2 hint 670/66.6 %.
- **Male order 13 or 14 at 12 kHz** (better men's F3): degrades women whenever an octave-down hint routes them to the male branch (48k f0/2: F2 173/15.0 %; 44.1k: 312/31.0 %). It also gives up the property that the hint no longer matters.
- **Male branch takes the female branch's rate and order (A)**: same as U at 44.1/48 kHz. At 16 kHz men F3 is 121/4.9 % against 93/3.6 % for U, and it keeps the female floor bug at 8 kHz.
- **Male-only rule (C)**: same as U at ≥ 11 kHz, but leaves women at 8 kHz capture at 672/66.7 %.
- **Dropping the pitch hint entirely (ceiling 5500 for everyone)**: at 44.1/48 kHz this is numerically almost the same as U (ceiling inert). It would need main-thread relay changes for no accuracy gain. A possible simplification later.
- **Changing the analysis rate (decimation 3 or 5 at 48/44.1 kHz)**: no consistent gain.
  - 44.1k at 14.7 kHz/order 14: women 127/8.4 % but men 113/8.0 %.
  - 48k at 16 kHz/order 16: men 102/7.0 %, women 136/9.9 %.
- **Longer anti-alias FIR or lower cutoff**: no gain (§4).
- **Moving the 140 Hz threshold**: immaterial once the order is rate-derived (§3).

## Follow-ups (not in this change)

- Women at 44.1 kHz would prefer order 10 at 11.025 kHz (F2 131/8.2 % vs 150/10.6 %). Men there want 12 (154/10.9 % at order 10), so a per-branch order would bring back hint sensitivity. Alternatively, 14.7 kHz analysis at order 14 gives women 127/8.4 % and men 113/8.0 %.
- Bandwidth cap 600 → 800 Hz: F3 improves for both genders at 44.1/48 kHz (§4).
- `tests/dsp/formant-debug.js` still has its own inline copy of an older configuration (order 10, 0.4/factor cutoff, `round(SR/11000)` decimation). It guards code that production doesn't run, and could import `formants.js` the same way.
